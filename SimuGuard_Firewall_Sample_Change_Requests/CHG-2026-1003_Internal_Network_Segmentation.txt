Short Description: Allow application servers to communicate with internal database servers

Assignment Group: Network Security Operations
Change Type: Normal
Priority: Medium
Category: Network Security
Subcategory: Internal Segmentation

Business Service: Enterprise Banking Application
Application: APP-003-BANKING
Environment: Production

Target Firewall: PAN-NGFW-DC-01
Firewall Platform: Palo Alto PA-5450
Management Platform: Panorama

Change Operation: Create Security Policy

Rule Name: Allow-Banking-App-To-DB
Source Zone: Trust-Application
Destination Zone: Trust-Database
Source Address: 10.200.10.0/24
Destination Address: 10.200.20.15/32
Application: postgresql
Service: tcp-5432
Protocol: TCP
Destination Port: 5432
Action: Allow
Security Profile Group: Strict-Enterprise-Security
Logging: Enabled at session end

Business Justification:
The banking application requires database connectivity to support transaction processing and customer account operations.

Implementation Plan:
1. Create a narrowly scoped internal firewall rule.
2. Allow only the banking application subnet to access the specified database server.
3. Restrict communication to PostgreSQL TCP port 5432.
4. Enable logging and security profiles.
5. Validate the proposed policy against existing segmentation controls.

Validation Plan:
Test database connectivity from the application subnet. Verify that unrelated network segments cannot access the database.

Backout Plan:
Disable the newly created rule and restore the previous network communication state.

Expected Impact:
No planned downtime. This change enables only the required application-to-database communication.

Requested Maintenance Window:
21 November 2026, 02:00–03:00 IST

Risk Assessment Requested:
Evaluate segmentation policy conflicts, database sensitivity, source and destination scope, application dependencies and blast radius.
